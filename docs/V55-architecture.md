# V55 构建与运行原理

V55 把任务调度、界面识别、输入和当日记录都放在 Android 设备上。电脑负责构建和验收，安装后的助手可在雷电 Android 14（x86_64）上独立运行。OCR 模型随包提供，Bing 加载内容、登录和同步积分仍需要网络。设备侧使用已授权、以 root 模式运行的 Shizuku。

## APK 是怎么构建的

1. **选定构建变体。** `capture-review` 模块用 `captureReviewDebug` 生成 V55。它从 `app` 共享界面、执行器、识别规则和测试，使用自己的清单和应用 ID 后缀。这样，跑过单测的 Java 逻辑和装进 APK 的逻辑出自同一组文件。
2. **装入设备所需的资源。** 构建时把 x86_64 原生库、OCR 检测模型、识别模型和字典打包。检测模型找出文字区域，识别模型读取局部区域中的字符。Gradle 依赖、SDK、原生库和模型在本机备齐后，构建可以离线完成。
3. **核对交付物。** 对同一份源码运行单测、组装 APK 和 Android lint。合并后比对 Git 文件树，再检查 APK 的签名、内容和 SHA-256。覆盖安装沿用原签名，设备上的当日记录得以保留。

## 技术栈与分工

| 层次 | 技术 | 在这个项目中的作用 |
| --- | --- | --- |
| 安卓界面与流程 | Java、Kotlin、Android View、Jetpack Compose | 显示入口和确认页。运行器依次调度基础任务、阅读和搜索，也提供独立搜索入口。 |
| 窗口与输入 | Android UiAutomation、Shizuku | 读取当前窗口和控件，确认来源后执行输入。提交和返回分别记录。 |
| 局部图像识别 | MaaFramework、JNA、ONNX 模型 | 在完整卡片内定位标题、数字或标识。识别点通过截图原点换算成屏幕坐标。 |
| 原生与构建 | C++17、CMake 3.22.1、JDK 17、Gradle 9.4.1、Android Gradle Plugin 9.2.1 | 编译原生桥接代码，选择模拟器对应的 ABI，打包模型和库。 |
| 验证 | JUnit 4、Android lint、雷电 Android 14 | 单测验证状态和预算，lint 检查 Android API 等问题，设备实测验证窗口切换、键盘和真实输入。 |

## 一轮任务如何执行

**基础任务。** 按签入、每日活动、更多活动的顺序处理。程序从 UI 结构找区域，滚动到卡片边框完整露出，再截取该卡的局部图像。进度已满的区域、已有完成勾的卡片和当天已尝试项会跳过。签入点击后原地复查。活动卡点击成功后至少等待五秒，返回一次，再用区域、标题、描述和分值寻找原卡。列表收缩或重排后，只有唯一匹配的任务才继续处理。

**阅读。** 进入新闻列表后才开始计数。每次在相同的屏幕区域重新定位一张完整卡片，检查来源栏固定位置的“广告”标识和点击点遮挡。文章打开后至少等待十秒，满足返回条件后回到列表，再向下滚动。完整流程使用每天最多七篇的入口。阅读记录分别保存打开和返回的结果。

**搜索。** 按小写 `a` 到 `t` 的顺序，每次只提交一个字符。确认是 Bing 的可编辑搜索框并已填入目标字母后，程序为该字母登记一次尝试，然后派发搜索。从提交命令成功返回时开始，用单调时钟计满五秒。程序确认结果窗口属于本次 Bing 任务且无遮挡后，只返回一次。整个过程无需读取结果标题或网页正文。

## 踩坑要点

| 现场表现 | 原因与处理 |
| --- | --- |
| 屏幕上能看见 Rewards，结构里却没有任务卡 | 网页绘制和 WebView 提供可访问节点可能不同步。先确认前台窗口，再等待区域结构就绪。任务来源仍不明确时停止。 |
| 返回后原来的第 2 张变成了另一项 | 完成卡片可能压缩、移动，屏幕序号只适用于当前画面。返回后重新匹配任务身份，重名且无法区分时跳过。 |
| 键盘一弹出，搜索被判为有遮挡 | 屏幕上会同时存在 Bing 窗口和输入法窗口。通过当前系统输入法配置核准包名及 UID，再核对窗口类型。其他浮层仍须消失，才能继续。 |
| 输入框已经可见，第一次却读不到光标 | 新建立的可访问连接有时先返回 Compose 外层视图，随后才返回真正获得焦点的编辑框。程序可短暂等待读取就绪，确认目标字母后才登记尝试。 |
| 命令已经退出，读取器偶尔仍报窗口格式错误 | 子进程退出时，输出管道可能还有最后一段数据。分别确认进程退出、读到流末尾和资源释放，之后才解析完整结果。 |
| 测试统计有二十次搜索，积分仍可能未满 | “已登记”“已提交”“已返回”是设备可以分别核实的事件。积分由服务端记录，须以 Rewards 页面显示的值为准。重启后保留当天已登记的字母，避免在提交结果不明时重复搜索。 |
